REVISION BATCH 5 - PART 9

Concern 4: Remove Status from the entire Performance Review feature.
- Performance Review does not require a Status field or approval-status workflow.
- Remove the Status column from every Performance Review list/table, including:
  - Pegawai Performance Review list.
  - Line Manager Performance Review list.
  - Pimpinan/selected employee Performance Review list.
  - Any Admin or monitoring list that displays Performance Review.
- Remove the Status label/value/badge from every Performance Review detail screen.
- Remove any Status dropdown, input, data card, validation, default value, or read-only display from the Performance Review add/edit form.
- Remove Status from Performance Review Patch, SubmitForm update logic, collections, shaped tables, and dummy/seed records.
- Do not generate values such as "Disetujui", "Menunggu Review", "Draft", or other approval states for Performance Review.
- Do not filter, sort, group, color, or control permissions based on PerformanceReview.Status.
- If the draft/test PerformanceReview table contains a Status column only because it was generated by the app, stop using it and remove it from the generated table schema where safe.
- If a connected external data source already contains Status and removing the physical column is unsafe, leave the source column untouched but completely exclude it from the app UI and formulas.
- Rebalance table widths after removing Status. The remaining list columns should be:
  - Tahun.
  - Semester.
  - Tanggal.
  - Line Manager, or Pegawai in the Line Manager view where appropriate.
  - Aksi / Detail.
- Expand the useful columns and keep the Aksi button aligned; do not leave an empty gap where Status previously appeared.
- Performance Review details should continue to show the actual review information such as employee, year, semester, date, Line Manager, Goal, Reality, Options, Will, Nilai/Ringkasan if supported, and Foto Bukti.
- Keep owner Edit/Delete permissions and Line Manager/Pimpinan read-only behavior unchanged. Removing Status must not weaken role authorization.
- Homepage badges such as "Sudah Diisi", "Perlu Diisi", "Belum Dimulai", and "Sudah Berakhir" are not PerformanceReview.Status values. Keep those badges and calculate them from record existence plus the active semester/period.
- Update dummy-data instructions from earlier batches so Performance Review seed rows do not require or display Status.
- Verify every Performance Review entry path. No form, list, detail, badge, formula error, blank column, or placeholder should reference PerformanceReview.Status.
